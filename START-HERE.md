# Задание для coding agent

Скопируйте блок ниже в новый чат coding agent и допишите контекст после строки `МОЙ КЕЙС`.

```text
Адаптируй этот репозиторий под моего личного Telegram-бота.

Сначала полностью прочитай AGENTS.md и SPEC.md, затем только релевантные docs.
Сохрани Telegram-only scope: не добавляй web UI, planner или публичный HTTP-сервер.

Обязательные инварианты:
- бот отвечает только владельцу, только в private chat;
- LLM создаёт только typed plan и не получает строки таблицы, secrets, shell, SQL или connector;
- trusted code проверяет source/columns/operators/limits и выполняет read-only запрос;
- неизвестный или неоднозначный запрос завершается уточнением без действий;
- update_id идемпотентен, исходящие ответы проходят через outbox;
- все примеры и тесты используют только вымышленные данные;
- реальные токены не проси отправлять в чат и никогда не печатай. Создай .env из шаблона,
  но попроси меня заполнить значения самостоятельно локально;
- writes/deletes/groups остаются выключены, если я отдельно и явно их не запросил.

Порядок:
1. Зафиксируй мою схему данных в config/sources.json и вымышленных fixtures.
2. Добавь/адаптируй connector. Для Google Sheets используй API с фиксированным spreadsheet/range,
   read-only scope и стабильным primary key; не browser scraping.
3. Добавь contract tests на мои реальные типы вопросов, но с вымышленными значениями.
4. Запусти bun install, bun run check и offline demo.
5. Выполни secret scan по working tree и всей git history.
6. Дай мне только список переменных, которые я должен заполнить локально, без их значений.
7. После заполнения запусти doctor и короткий live smoke на тестовом боте.

МОЙ КЕЙС
- Для чего бот:
- Где таблица:
- Название листа/range:
- Стабильный ID строки:
- Колонки и их смысл:
- 10 типичных вопросов:
- Часовой пояс:
- Нужен ли голос:
- Нужны ли записи/изменения (по умолчанию нет):
```

Не вставляйте под этим заданием токен Telegram, private key Google или содержимое приватной таблицы. Достаточно названий колонок и вымышленных примеров.
